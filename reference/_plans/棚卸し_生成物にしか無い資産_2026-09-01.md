# 生成物にしか無い資産 — フィールド単位の完全棚卸し

全数node検証。サンプリングなし。repo未変更。詳細JSON = `inv/legacy_only_assets.json`。

## 結論(先に要点)

master/*.json だけから legacy 3ファイルを再現しようとすると、**構造(型/技/特性/持ち物の骨格)は再現できる**が、以下7点は**master に無い**:

1. **TYPE_KANJI/TYPE_DISPLAY/TYPE_OFFENSIVE_STATS/DEFAULT_TYPE_ORDER** — 静的4テーブル、master/types.jsonはname+colorのみ
2. **POKEMON_LIST.season**(245件、履歴配列) — master/regulations.jsonは「過去は残さない」設計なので M-A の履歴が消えている
3. **WAZA_MAP.availability**(919件全部) — Showdown由来(reference/_showdown/moves.json)、masterに未移送
4. **ABILITY_DESC本文** — 家の流儀(短文)と master.effect_ja(ヤックン権威・長文)が**別物**(国内309件中308件不一致・Champions195件中195件不一致)。意図的仕様だが「旧ページの文言は再現不可」という意味では legacy_only
5. **STAT_RANK** — masterに欄自体が無い(が式で再現可能・式は検証済み)
6. **items_database.js の30種の構造化フィールド**(acquisition/restriction/notes/q12/factor/boost_type/heal_*/proc_chance等) — masterはeffect_ja(自由文)+applies_to系3本だけ
7. **POKEMON_LIST の行順**(4段バケット: 全種1周→追加フォルム→メガ→地方フォルム) — masterはno+name単純ソートで別物

加えて **Champions版 pokechan_data.js だけの170個の技フラグ列**(`mamoru`,`chouhatsu`…)は POKEMON_WAZA/learnsets からの単純導出ではない(867/6866値が食い違う)。ただし **master/learnsets.json は legacy より完全**で、867件中699件(81%)を自動解決する。残る168件はほぼ全部(34体)Champions独自メガ(メガライチュウX/Y等、公式に存在しないオリジナル進化)。

**行順**: no昇順の単純ソートではない。実測=4段バケット構造: ①全種1〜1025を1周(各種の代表フォルム) → ②地方/メガ以外の追加フォルム(デオキシス等、no昇順) → ③メガ全部(no昇順) → ④地方フォルムを**地方ごとにグループ化**(アローラ→ガラル→ヒスイ→パルデアの順)、各グループ内はno昇順。この束ね方は`reference/pokeapi_master.json`(PokeAPI取得順)をそのまま引き継いでいるだけで、明文化されたソートキーではない。**master/pokemon.jsonは(no,name)の単純ソートで別物** → 行順を再現するには①元の取得順を保持する欄を足すか②この4段バケット規則をビルダーに再実装する必要あり。**未検証=再現ルールとして確定していない**。

### ABILITY_DESC

| | legacy件数 | masterに同一と一致 | 不一致 |
|---|---|---|---|
| 全国版(A.ABILITY_DESC) | 309 | 1 | 308 |
| Champions版(C.ABILITY_DESC) | 195 | 0 | 195 |

master限定(全国版に無い)= 118件。**理由**: master/abilities.json.effect_ja は `tools/build_master_v2.js:180-185` で**Champions権威コーパス(ヤックン/ch/)の文を最優先**にする設計。legacyの「家の流儀」短文(例:「毎ターンすばやさ+1。」)と、masterの権威長文(例:「毎ターン、『すばやさ』ランクが1段階ずつ上がる。」)は**別の文章**。CLAUDE.mdの「ABILITY_DESCは公式準拠なのでそのまま可」という方針とは整合するが、**旧ページの文言をそのまま再現することはできない**(内容の質は上がるが、これは"データ移行"ではなく"文言の置き換え"になる)。

## 2. pokechan_data.js(Champions版)だけが持つ追加列

POKEMON_LIST各行(313件)に、全国版には無い**196キー**が乗っている。

- **cnt4/cnt2/cnt1/cnthf/cntqf/cnt0/cnt42/cnthfqf**(8列): resist配列からの単純集計(4倍/2倍/1倍/0.5倍/0.25倍/0倍カウント、cnt42=cnt4+cnt2、cnthfqf=cnthf+cntqf)。**computed**、かつ実は`pokemon_db_v9.html:1561-1574`の`recalcResistCounts()`で**画面表示時に毎回再計算されており、JSON側の値は現在すでに使われていない**(死んだ列)。
- **okatazuke**: 唯一の非boolean列(サンプルは常に0)。用途未確認、要フォローアップ。
- **170個の技フラグ列**(`mamoru`,`chouhatsu`,`negoto`…、値=そのポケモンがその技を覚えるか): `pokemon_db_v9.html`の技別フィルタチェックボックス列(2144〜2987行)が使用。

**技フラグ列の全数照合**(313体×169キー=52,897ペア中、boolean型のみ):

| 比較先 | 不一致 |
|---|---|
| legacy `C.POKEMON_WAZA`(旧learnset) | 867件(true側)+20件(false側) / 全true数6866 |
| → うち master/learnsets.json の `learn[]` で解決 | 699件(81%) |
| → それでも未解決 | 168件、**34体に集中**(ほぼ全部Champions独自メガ: メガライチュウX/Y・メガラグラージ・メガシビルドン・メガタイレーツ・メガクチート・メガカラマネロ等=公式に存在しない架空進化のため、権威スクレイプに movepool が無い) |

**結論**: これらのフラグ列は概ね(81%)master/learnsets.jsonの方が正確・完全で再現可能。**残り168件だけが真の legacy_only**(架空メガの技覚え情報)。
