## 4. Claudeが再実行した結果(実機・Astraが回せなかった分)

worktree を `python3 -m http.server 8000 --bind 127.0.0.1` で配信して実行。

### 4-1 `node tools/_views_pdca_playwright.js` → **7/8 ❌**(items_list.html のみ✅)

- **名簿・種族値の全件照合は全部一致**(pokemon 323/323・1273/1273、abilities 313、items 423、moves 919、party_checker items=181)。Astraの主目的は動いている。
- 赤の原因(欠陥A): 新設の `requestfailed` リスナーが **外部の計測ビーコン**(`google-analytics.com/g/collect` の `net::ERR_ABORTED`、`raw.githubusercontent.com/.../froslassite.png` の `ERR_BLOCKED_BY_ORB`)をエラーに数える。旧版は `requestfailed` を見ていなかったので出なかった。**オリジン(127.0.0.1:8000)以外を除外する1行が無い**。故障注入スクリプトでは外部を204に置換しているのに、本番ゲート2本には入れなかった。
- 赤の原因(欠陥B): `real_battle.html` の probe が `window.ITEMS_DATABASE.items` を無条件に読む → `TypeError: Cannot read properties of undefined (reading 'items')`(外側ページにその global が無い。simは iframe の中)。旧版は `typeof ITEMS_DATABASE!=="undefined"` で守っていた。party_checker では同じ probe が通る(そちらは global がある)。

### 4-2 `node tools/i18n_audit_playwright.js <8言語> --page=pokemon_db.html|pokemon_db_all.html --strict` → **exit 1 ×2**

- 残日本語 **0件**(ページは正常)。赤は全部 欠陥A と同じ外部ビーコン(pokemon_db 8件・pokemon_db_all 15件、`pagead2.googlesyndication.com` 含む)。

### 4-3 `node tools/_browser_audit_faults_playwright.js` → **10/12 ✅**、`masterDelay` が両ページ ❌

- 出た残日本語: `全▾` `除外▾` `全解除` `閉じ`(multi-select のボタン)。
- **これは検証器のバグではなく、既存 `pokemon_db.html` / `pokemon_db_all.html` の本物の競合バグ**(Astraが触っていない main と同じコード):
  - `refreshAllI18nContent()` は `if (typeof dbReady !== 'undefined' && !dbReady) return;` で早期return(`pokemon_db.html:4875`)
  - master が遅くて `i18n:ready` が先に来るとここで抜け、後から `dbReady=true → init()` で thead/ms ボタンを組み立てても **誰も `I18N.apply()` を呼ばない**(`:4993` 以降に呼び出しなし)
  - = CLAUDE.md の既知の罠「JSで組み立てるUI部品は i18n:ready/i18n:changed での再描画までがセット」の取りこぼし。回線が遅い実ユーザーの EN 画面でボタンだけ日本語になる。
  - **Astraの故障注入テストが、Astra自身は回せないまま、実在バグを1件掘り当てた**(検証器としての価値の証拠)。
