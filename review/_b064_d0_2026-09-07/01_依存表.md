## (d) undo — 巻き戻し機構

### エンジン本体(`real_battle_simulator.html`)

- `battleHistory`(5372行、配列。`HISTORY_MAX=50`)に`snapshotBattleState()`(5378〜5459行)の戻り値を`pushHistory()`(5482行)で積む。
- `pushHistory()`の呼び出し箇所は3か所: `runSingleAttack()`内(5630行・1回攻撃ごと)、`runTurn()`冒頭(6963行・毎ターン頭)、`startBattle()`内(8035行・開戦時)。
- `snapshotBattleState()`は`{ self: snap(sides.self), opp: snap(sides.opp), log: battleLog.map(...), lastMoveAny: lastMoveAnywhere || null }`を返す。**`sides.self`/`sides.opp`という固定2キーを個別に呼ぶハードコード**(ループでなく2行の直書き、5393-5394行)。
- `snap(st)`(5378行内の内部関数)がコピーする項目は**現在HP・状態異常・能力ランク・ほぼ全ての揮発状態(こんらん/やけど/こだわりロック/ばけのかわ/メガシンカ済みフラグ/控え(bench)の技・努力値など)を明示的に1個ずつ列挙**(約60項目、5379〜5458行)。新しい機構を足すたびに**この列挙にも追記が要る**設計(汎用シリアライズでなく手書き対応リスト)。
- `undoBattle()`(5493行)は`battleHistory.pop()`したスナップショットを`restore(st, src)`(5507行の内部関数、5507〜5556行)で`sides.self`/`sides.opp`それぞれに書き戻す。復元対象項目は`snap()`と対になるよう手書きで並んでいる(同じく約60項目)。
- **`env`(天候/フィールド/トリックルーム等)はこの`snapshotBattleState()`/`undoBattle()`の対象に含まれていない**(戻り値のトップレベルキーは`self`/`opp`/`log`/`lastMoveAny`のみ、`env`キーなし=5393-5397行を実読して確認)。**エンジン自身のundoは「場の状態」を戻さない。**

### `battle_lab.html`側の補完層

- `battle_lab.html:4444`のコメント「エンジンが持たない env / ページ表示(ターン番号・右ログDOM・ダメージピン)は labUndoSnap から復元する。」が上記の欠落を明言している。
- `executeTurn()`内(`battle_lab.html:4550`付近)で、エンジンの`pushHistory`とは別に**ページ側が独自に**`labUndoSnap = { env: JSON.parse(JSON.stringify(S.env)), turnNo, lastLogTurn, logHtml: ..., pin: ... }`(4551〜4556行)を毎ターン保持する。
- `labUndoTurn()`(4454行)は`w.undoBattle()`(エンジン本体のundo、4562行付近で呼ぶ)を呼んだ**直後に**、`Object.keys(S.env).forEach(k => { delete S.env[k]; })`(4563行付近)のような形で`env`をページ側スナップショットの中身に手動で書き戻す。つまり**undoは「エンジンのbattleHistory」と「ページのlabUndoSnap」の二重構造**で、片方(env)はエンジンが担当しない。
- `labUndoSnap`は「深さ1」固定(`labUndoTurn()`内で`labUndoSnap = null`と即座にクリア=4460行、コメント「連打で2手は戻れない」)。`battleHistory`自体は`HISTORY_MAX=50`まで積めるが、UI(バトルラボ)は直近1手にしか使っていない。
